# Potential backlog

These ideas remain unselected possibilities. They do not create current
obligations and require separate design and acceptance before they can become
operating guidance.

## Compact internal working state

- **Potential outcome:** define a minimal, refreshable internal state that helps
  a model retain the active objective, contract, evidence generation, and next
  falsifiable action across a long task.
- **Dependencies and next action:** compare the existing contract, phase gate,
  and continuity mechanisms; design only if a distinct state representation
  removes demonstrated loss without duplicating those owners.
- **Acceptance evidence:** controlled long-task cases show fewer lost
  obligations and stale assumptions without adding ceremony to fast work.

## Omission recovery procedure

- **Potential outcome:** give a model a bounded recovery path after it discovers
  that a material consumer, witness, obligation, or evidence dependency was
  omitted.
- **Dependencies and next action:** classify omission types and map each one to
  the earliest affected step in the existing material-change loop.
- **Acceptance evidence:** representative recovery cases resume at the correct
  boundary, invalidate only dependent evidence, and avoid restarting unrelated
  completed work.
